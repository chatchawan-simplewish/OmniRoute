# OmniRoute V49 fresh-realm token-page readiness design

## Purpose and predecessor disposition

V47 is consumed and failed cleanly at trusted-listing validation. Its exact
historical rejecting condition remains **NOT PROVEN**. V47 must never be
retried, continued, reused, reinterpreted, or relaxed.

V48 is consumed. Its first fixed sanitized diagnostic payload shows that every
V47 trusted-listing semantic predicate passed against the observed rank-zero
record shape. That payload was produced before any cleanup query, contains no
raw listing or secret data, and records zero claim, navigation, DOM, clipboard,
or provider-mutation attempts; it is acceptable only as non-authorizing design
input for V49.

V48's first permitted state-only cleanup expression then failed locally with a
`ReferenceError` because it referenced a nonexistent global counter variable.
A second corrected state-only expression was run before the realm reset. That
two-query cleanup deviation did not invoke a browser API or mutate provider
state, but it departed from V48's reviewed one-query cleanup procedure. The
second query is transparent, non-authorizing incident evidence only and is not
precedent for retry, correction, or continuation. V49 relies only on the first
fixed sanitized diagnostic payload plus the eventual confirmed realm reset.
V48 did not claim a tab and cannot authorize adoption. V48 must never be
retried, continued, reused, reinterpreted, or relaxed.

V49 is a new, independent one-shot gate. It is the smallest clean reissue of
the reviewed V47 attachment and token-page semantic-readiness contract. It
uses the V48-confirmed V47 predicates unchanged; it makes no claim about the
cause of V47's historical failure and does not consume or extend either prior
gate.

## Minimal implementation delta

The implementation is limited to:

1. mechanically deriving a new V49 executable and pure fixture from the final
   reviewed V47 candidates;
2. renaming only V47-owned declarations, fixed state/result literals, and
   fixture labels to V49;
3. extending the fresh-realm predecessor guard and direct declaration audit to
   require the established V35-V48 declaration set absent; and
4. retaining the exact V47 trusted-listing, attachment, account-home, token-page,
   counter, output, privacy, cleanup, and downstream-binding semantics.

No new browser API, abstraction, fallback, retry, alternate selector, alternate
URL, timing relaxation, manual integration path, or provider action is added.
The fixed non-secret search text remains
`OmniRoute secure console R5 20260901`.

## One-shot runtime and attachment contract

V49 runs only in a freshly reset persistent CUA Node realm. Before its sole
live send, a fixed direct `typeof` audit must prove every named V35-V49
predecessor and candidate declaration absent. The exact executable may be sent
only once.

The attachment stage performs exactly one of each reviewed operation:

- pinned runtime import;
- setup invocation;
- named `chrome` browser connection;
- complete pinned documentation read and terminal write;
- reviewed session-name assignment;
- `openTabs()` call; and
- after every cached listing predicate passes, claim of the exact returned
  rank-zero record.

It must not reconstruct a tab reference from an ID. It must not inspect or
attempt any later-rank record. It must not call claim, navigation, wait, page
URL read, snapshot, or DOM methods before the complete trusted-listing result
is true.

## Exact trusted-listing predicates

V49 preserves the final V47 predicates proved by V48:

- the listing is an array with zero own symbols, a safe bounded data `length`,
  exact own canonical index names, and own enumerable data descriptors for
  every index;
- rank zero is a non-null object with the ordinary object prototype at bounded
  depth, zero own symbols, only documented allowed own keys, safe own
  enumerable data descriptors, and no accessors;
- the required `id` is a bounded safe non-control string;
- each optional documented key may be absent, but every present optional value
  must be a bounded non-empty control-free string; a present optional key whose
  value is `undefined` is rejected by the strict V47 all-values predicate;
- if `url` is present, the cached safe string parses with the cached standard
  `URL` constructor to HTTPS, exact hostname `dash.cloudflare.com`, empty port,
  empty username, and empty password; and
- only the already-validated exact rank-zero record is supplied once to
  `claimTab`.

Raw listings, descriptors, prototypes, records, identifiers, titles, URLs,
URL components, group values, and provider metadata are never output, logged,
committed, or placed in evidence. Cached structural values and parsed URL
components are cleared before terminal output.

## Account-home and token-page readiness

After exact adoption, V49 preserves the reviewed V47 downstream sequence:

1. navigate the owned tab once to the fixed Cloudflare account-home URL;
2. wait within the reviewed bound, read the URL once, and validate exact HTTPS
   host plus the 32-lowercase-hex account-home path;
3. take the reviewed semantic snapshot and require exactly one `mysw.me` zone
   link, a positive anchor count, and zero busy indicators;
4. navigate once to `https://dash.cloudflare.com/profile/api-tokens` and read
   the resulting URL once;
5. construct the unique textbox locator named `search api tokens`, wait at most
   20 seconds for visibility, and require count exactly one;
6. validate its bounded `aria-controls` ID and unique controlled result root;
7. require one visible paginator and prove the empty initial filter plus complete
   baseline paginator, row, and status state;
8. fill the fixed non-secret search text once and wait for both exact query echo
   and exact empty status; and
9. prove exact filter value, terminal `0-0 of 0`, zero rows, both navigation
   buttons disabled, no busy state, exactly one Create Token control, and zero
   exact token-name or matching-row occurrences.

The downstream readiness counters remain exactly four attempts and four
fulfillments on PASS: search-control visibility, paginator visibility, query
echo, and empty status. Every inherited V47 completeness counter must retain
its reviewed exact value.

Create is counted but never clicked. V49 contains no Copy, clipboard,
credential, token-secret, storage, cookie, DNS, routing, VM mutation, provider
mutation, tab creation or close, reconnect, retry, fallback, override, verdict
relaxation, or manual-continuation path.

## Success, failure, privacy, and cleanup

V49 is consumed at the start of its only live send. Any exception, timeout,
drift, unexpected value, incomplete counter, failed terminal write, or cleanup
doubt spends the gate and stops permanently.

Operational catches are unbound. Output is limited to fixed state/result/error
literals, bounded booleans, approved bounded counts, exact counters, and the
fixed-schema attachment result. Thrown values and raw browser/provider/DOM data
are never inspected or serialized.

On exact PASS, only the V49 owned token-page task-tab binding and its minimal
eligibility, state, and consumption flags may remain for the separately reviewed
downstream pre-Create cell. The attachment tab, setup function, agent, Chrome
controller, documentation, listing, descriptor, record, URL, snapshot, and
broad runtime aliases must be cleared before the output proves sole-binding and
no-residue.

On any failure or uncertainty, V49 clears both V49 tab bindings, eligibility,
all broad aliases, and cached data, emits at most its fixed sanitized terminal,
and stops consumed/ineligible. A terminal-output failure repeats cleanup and
rethrows without inspecting the thrown value and without a second write.

After any failed or uncertain result, only one fixed state-only cleanup proof is
allowed, followed by immediate realm reset and one sanitized incident artifact.
If that one proof fails, no corrected or second query is allowed; reset the
realm and record the uncertainty. No V49 retry, continuation, fallback, reuse,
reinterpretation, or verdict relaxation is permitted.

## Verification and independent review gate

Before live execution, V49 requires:

1. one exact executable and one smallest pure fixture;
2. syntax PASS and a fixed `V49_PURE_FIXTURES_PASS` result covering predecessor
   contamination, trusted-listing structural and URL failures, an absent
   optional key that may pass, a present-`undefined` optional key that fails
   before claim, async token-page readiness, counter completeness, output
   privacy, one-proof-only failure cleanup, and exact PASS retention;
3. a committed direct-byte/hash review package proving the implementation is
   limited to the declared V47-to-V49 mechanical delta;
4. independent `gpt-5.6-sol` High review with zero unresolved Critical, HIGH,
   IMPORTANT, or Minor findings and an exact PASS verdict;
5. a later non-self-referential execution-classification commit whose parent is
   exactly the PASS review commit;
6. a separate post-commit coordinator tuple proving exact commit/parent chain,
   fixed exclusions, candidate hashes, empty index, preserved exact 12-path
   dirty baseline, and unchanged outside projection;
7. action-time revalidation of candidate/runtime/documentation pins, clean
   evidence worktree, public DNS absence, zero local residue, VM1205 safe
   checkpoint, sole authority ownership, and current task identity;
8. a fresh CUA realm whose first call is exactly `await cua.getState();`, the
   fixed declaration audit, and a new external confirmation naming Chrome
   Profile `Codex-Chrome-Bell-PC2`, the intended window, and the intended
   Cloudflare API Tokens tab; and
9. explicit evidence that no other task controls that tab or the same
   Cloudflare token object.

No live send is allowed before all nine requirements pass. Any mismatch stops
fail-closed and requires a separately designed and reviewed successor gate.

## Mandatory later confirmations

The final Create/native Copy/native masked Paste confirmation remains external,
mandatory, action-time, and unreached. After Create, the agent must not inspect
the generated-token page or clipboard; the owner alone performs the reviewed
native Copy, native masked Paste, generated-page close, and Enter sequence.

The later exact-row deletion confirmation remains separate, mandatory, and
unreached. Standing unattended authority and recommendation preapproval do not
waive either confirmation.
